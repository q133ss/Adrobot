# Ответы на вопросы по тестовому

## Как я использовал ИИ-агентов

Работал в связке с кодинг-агентом (Claude через OpenCode) как с джуном, которому нужен
чёткий контекст и проверка результата. Что было на агенте и как это контролировалось:

1. **Сбор требований и документации.** Notion-страница с ТЗ закрыта от анонимного
   просмотра, но публично расшарена: вытащил текст и скриншоты через публичный API
   Notion. Дальше — `admin-api.docs.keitaro.io/openapi.json`: агент разобрал спецификацию,
   выписал схемы Campaign/Stream/Offer/Report и использовал их как источник правды
   вместо догадок по скриншотам.
2. **Планирование и каркас.** Агент предложил структуру слоёв (клиент Keitaro →
   сервисы → роуты → шаблоны), сгенерировал проект, модели, миграции, тесты и фейковый
   трекер для локального запуска без ключа.
3. **Итерации под тестами.** Каждый шаг проверялся `pytest` (87 тестов) и `ruff`.
   Агент писал тесты вместе с кодом, включая негативные сценарии (откат кампании при
   ошибке второго потока, удаление последнего оффера, недоступный трекер).
4. **Браузерная автоматизация.** Playwright-сценарий логинился в реальный Keitaro,
   создавал кампанию через форму, добавлял оффер и снимал скриншоты. Это поймало
   проблемы, которые юнит-тесты не видят: кодировку urlencoded-форм в Starlette
   (`Кампания` → `ÐšÐ°Ð¼Ð¿Ð°Ð½Ð¸Ñ`) и экранирование кавычек в Alpine `x-data`.
5. **Проверка на живом API.** После подключения реального ключа агент прогнал создание
   кампании и редактирование офферов на `tlgk.host`. Это выявило расхождения Swagger
   с реальностью, которые пришлось исправить:
   - `GET /groups` требует обязательный `type=campaigns|offers`;
   - редирект в Keitaro — это `action_type=http`, а не `redirect`;
   - у потока с офферами (`schema=landings`) тоже `action_type=http`;
   - `/report/build` отдаёт `rows` объектами, без `meta`;
   - у оффера `country` может быть пустой строкой, а не массивом.
6. **Ревью и продуктовые решения.** Агент не принимал за меня решения в спорных местах:
   режим гео-фильтра (в ТЗ буквально «из страны → на Google», что убивает офферный
   трафик), один поток с офферами вместо потока на оффер, обязательность домена.
   Эти пункты вынесены в README и в вопросы к заказчику.

Что НЕ отдавал агенту: доступы, финальное ревью, выбор стека (FastAPI/SQLAlchemy были
в ТЗ, фронт выбрал серверный рендеринг + Alpine), продуктовую логику редактора.

## Что не успел / что бы доделал

**Не вошло в сдачу:**

- **Авторизация и CSRF.** Сервис рассчитан на внутренний контур; перед публикацией нужен
  логин, роли (кто может менять кампании) и защита форм.
- **Серверная пагинация кампаний.** Сейчас дашборд забирает список кампаний одним
  запросом и показывает последние 50 + поиск. На трекере с 5000+ кампаний нужен
  серверный фильтр/пагинация (в API есть `limit`, но поведение отличается по версиям).
- **Редактор нескольких потоков с офферами.** Меняется первый найденный поток; остальные
  показываются только для чтения.
- **Клонирование кампаний, массовое создание из CSV, A/B потоков и автостоп убыточных
  офферов по ROI** — очевидные следующие фичи для реальной работы.
- **Надёжность интеграции:** ретраи с backoff на 5xx/таймауты, ограничение частоты
  запросов, структурные логи и метрики, health-check с детализацией.
- **CI и контрактные тесты:** GitHub Actions (pytest + ruff), а также запись ответов
  реального Keitaro в фикстуры, чтобы ловить изменения API без живого трекера.
- **Инфраструктура:** `docker-compose` с Postgres, отдельная миграция для Postgres
  (сейчас проверено на SQLite), фоновый синк зеркала по расписанию.
- **Продвинутая статистика:** отчёт по дате конверсии, больше метрик (approve, rebills),
  кэширование отчётов, сравнение периодов.
- **Видео-демо редактора из ТЗ** посмотреть не удалось: ссылка ведёт на «Интро etolegko».
  Логику восстановил по тексту ТЗ; если в видео есть нюансы (например, отдельный поток
  на каждый оффер) — поправлю.

**Что сделано после проверки на живом трекере:** исправлены `type` для групп,
`action_type=http`, парсинг `country` у офферов, добавлен поиск и лимит на дашборде,
починена кириллица в формах. Тестовые кампании и лишний API-ключ на `tlgk.host`
удалены после проверки.
